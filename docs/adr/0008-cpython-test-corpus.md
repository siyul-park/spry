# 0008: CPython test corpus

- Status: Accepted

## Context

CPython 3.14 is the oracle for spry's front end, and its `Lib/test` suite is the broadest public specification of the grammar, tokenizer, and syntax errors. spry needs that coverage, but vendoring CPython wholesale bloats the repository, and fetching everything at test time makes normal `go test` depend on the network. CPython test files also embed expected strings that may not match 3.14.9 exactly, so they are unsafe to trust as expectations.

## Decision

Pin CPython 3.14.9 and use a hybrid corpus:

- Small cases (`test_ast/snippets.py` lists, doctests, string arguments of syntax-check helper calls, `check_tokenize` inputs) are extracted into checked-in JSONL manifests owned by the package under test, with PSF attribution in `testdata/cpython/NOTICE`.
- Whole files (stdlib `Lib/**/*.py`, `Lib/test` files, `tokenizedata`, badsyntax files) are fetched from the pinned tag tarball into the gitignored `.cache/cpython/3.14.9/` (override `SPRY_CPYTHON_CACHE`), verified by sha256, and skipped when absent.
- Expectations are regenerated by running `python3.14` on the extracted inputs; expected strings in CPython test files are never trusted. `ast.parse` success means the frontend accepts the input; failure means an error case with type, message, line, 1-based code-point offset, end line, and end offset. Failures only visible to `compile` are recorded as stage `compile`.
- Each package keeps a known-failure ratchet `testdata/cpython/xfail.txt`: listed IDs must fail, a listed case that passes fails the test, the list only shrinks, and a layer exits when it is empty.
- `make corpus` fetches, `make corpus-extract` regenerates manifests, and a CI drift job fails on manifest diffs.

Details are in `docs/testing.md`.

## Consequences

- Normal `go test` needs neither network nor Python; manifests are small and reviewable.
- Whole-file coverage is available locally and in CI without vendoring.
- The repository carries PSF-licensed excerpts and must keep the NOTICE file accurate.
- Upgrading the pinned version is an explicit change: re-extract, review manifest diffs, update the sha256.
- The ratchet makes frontend progress measurable and prevents silent regressions.

## Alternatives

- Pure cache: fetch everything at test time. Rejected because small, high-value cases would be unavailable offline and CI would depend on network availability.
- Vendor all: check in `Lib/test` and the stdlib. Rejected because of repository size, license surface, and review noise for files spry never edits.
