# Benchmarks

Methodology for comparing spry against CPython, PyPy and gpython. The harness lives in the separate Go module `benchmarks/` (joined to the repo by `go.work`), so benchmark dependencies do not enter the main module.

## Runners

| Runner | Command | Availability |
|---|---|---|
| `cpython` | `python3.14`, or the interpreter named by `SPRY_PYTHON` | Required baseline |
| `pypy3` | `pypy3` on `PATH` | Optional |
| `gpython` | https://github.com/go-python/gpython (`gpython` on `PATH`) | Optional |
| `spry` | built `cmd/spry` | Available from P3 |

Interface (Go):

```go
type Runner interface {
    Name() string
    Available() bool
    Run(fixture Fixture) (Result, error)
}
```

A runner that is not available is reported as `skipped`, not failed. The `spry` runner is unavailable until execution lands (P3).

## Fixtures

`benchmarks/fixtures/*.py` are Python kernels adapted from minivm's benchmark suite (https://github.com/siyul-park/minivm/tree/main/benchmarks/fixtures): allocation-graph, binary-trees, branch-tree, closure-counter, fannkuch, fnv1a64, i64-wide-fib, indirect-recursive-fib, iterative-fib, mandelbrot, mat-mul, n-body, n-queens, permutation-flips, recursive-fib-20, recursive-fib-35, sieve, sort-stress, spectral-norm, string-build, struct-tree-walk, tail-ping-pong, tail-sum, typed-array-sum, xorshift-i64.

Each fixture:

- is a valid Python 3.14 program in the phase-1 subset;
- prints a deterministic result to stdout, and has an `.expected` file generated by CPython;
- runs the kernel in a function called from module level, with parameters fixed in the file.

A runner's output must equal `.expected` for the sample to count; a mismatch is a failure, not a slow result.

## Measurement

| Parameter | Default | Notes |
|---|---|---|
| Warmup runs | 2 | Discarded; lets PyPy JIT and caches settle |
| Repetitions | 10 | Whole-process runs, wall clock |
| Statistic | median, plus min and max | Median reduces outlier noise |
| Timeout per run | 60 s | Timeout is reported, not averaged |

Two timings are recorded per sample:

1. **Total**: process start to exit.
2. **Kernel**: time reported by the fixture itself via `time.perf_counter()` around the kernel call (when `time` is available to the runner; otherwise omitted). Kernel time excludes interpreter start and compilation, which is how spry's compile time is separated from execution time. spry's compile time is also reported on its own (`-X spry.dump` timing).

Process-level measurement is used for every runner so they are compared by identical rules; in-process Go benchmarks live elsewhere.

## Environment Capture

Every report records: date, git commit, OS/arch, CPU model and core count, Go version, versions of each runner (`python3.14 -V`, `pypy3 -V`, gpython version), spry build flags and `-X spry.opt` level, and whether the system was on AC power (when detectable). Reports without this block are rejected by the report check.

## Running

```sh
make bench                      # all fixtures, all available runners; updates the results section below
cd benchmarks && go run ./cmd/bench -runner cpython -fixture recursive-fib-20
```

Flags: `-runner` (repeatable), `-fixture` (glob), `-warmup`, `-reps`, `-json <path>` for raw samples.

## Interpreting Results

- Report speedup versus CPython per fixture and the geometric mean across fixtures.
- Compare like with like: spry O2 default versus CPython default; PyPy results after warmup only.
- A regression gate (once a baseline file is committed) fails when a fixture slows by more than 10% against the baseline on the same machine class; cross-machine comparisons are informational.
